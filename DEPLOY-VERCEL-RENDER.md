# WYRMORA MEDICAL — Vercel + Render deployment

This bundle is configured for Vercel (Vite frontend), Render (Express API), and Render managed PostgreSQL.

## Before deployment

The app is an educational medicine information directory, not a licensed pharmacy or clinically verified medicine database. Have a qualified pharmacist/clinician review each medicine record, Nepali translation, warnings, prescription status and source/version. No invented retail prices are seeded. Do not activate medicine sales, prescription fulfilment, pharmacy promotion or payment until the applicable Nepal permissions and licensed pharmacy/supplier workflows are in place.

The included Render Blueprint selects paid baseline plans because Render's free Postgres databases expire after 30 days and free services are not intended for production. Review current costs in your Render account before approving creation.

## 1. Push to GitHub

1. Extract this ZIP.
2. Create a private GitHub repository named `wyrmora-medical`.
3. Push the **contents** of `WYRMORA-fullstack` to the repository root. `render.yaml`, `package.json`, `client/` and `server/` must be at root.
4. Never commit `.env`, passwords, API keys, database dumps or patient information.

## 2. Create Render API and database

1. Sign in at https://dashboard.render.com/ .
2. Choose **New → Blueprint**, then connect the GitHub repository.
3. Confirm the `wyrmora-medical-api` web service and `wyrmora-medical-db` PostgreSQL database, both in Singapore. Review the displayed costs.
4. Apply the Blueprint and wait for deployment.
5. Test `https://wyrmora-medical-api.onrender.com/api/health`; expected JSON: `{"status":"ok","service":"wyrmora-api"}`.
6. In Render → API service → Environment, reveal/copy `MEDICINE_ADMIN_KEY` for your private admin use. Never put it in frontend code, GitHub or a public chat. `JWT_SECRET` and `MEDICINE_ADMIN_KEY` are generated by Render.

If Render gives the service a different hostname, update `client/vercel.json` destination to `https://YOUR-ACTUAL-API-HOST.onrender.com/api/:path*` and push that change before deploying Vercel.

## 3. Deploy frontend to Vercel

1. Sign in at https://vercel.com/dashboard/ and import the same GitHub repository.
2. Set **Root Directory** to `client` (required).
3. Framework: Vite; Build command: `npm run build`; Output directory: `dist`; Install command: `npm install`.
4. Name the Vercel project `wyrmora-medical` so its default production URL is `https://wyrmora-medical.vercel.app`.
5. Deploy. `client/vercel.json` proxies `/api/*` to Render so the browser uses same-origin API requests.

If the Vercel production domain differs, change Render `CLIENT_ORIGIN` to the exact origin (no trailing slash). For multiple domains, comma-separate them, e.g. `https://wyrmora-medical.vercel.app,https://medical.example.com`, then save and redeploy Render.

## 4. Verify

1. Open the Vercel production URL and search `Paracetamol`.
2. Test `https://YOUR-VERCEL-DOMAIN/api/health` — it should return the API health JSON.
3. Open Admin, enter the private `MEDICINE_ADMIN_KEY`, and save a test-only pharmacist-reviewed record. Refresh and verify it persists. Remove test content before launch.
4. Check Render logs for migration, database and origin errors. A page rendering from its local read-only fallback does not prove the database is connected.

## 5. Production operations

- Keep `NODE_ENV=production`, `COOKIE_SECURE=true`, and a unique 32+ character JWT secret.
- Keep secrets only in Render's environment settings; rotate them if exposed.
- Set up backups and test restoring the database before storing business-critical records. Monitor usage, logs, database storage and billing.
- The current medicine Admin is protected by a shared API key, not staff identity/MFA. Before public operation, implement named admin accounts, MFA, role permissions, audit logs and stronger write controls.
- Run `npm install`, `npm test`, and `npm run build` locally before releases.
- Do not store patient health histories until a privacy/security review and compliant consent/retention policy are implemented.

## What is not automated

You must connect your own GitHub, Render and Vercel accounts and approve deployment/billing. This package cannot register a pharmacy, obtain DDA approval, provide live verified medicine prices, configure a payment merchant account, or generate a public production URL by itself. Pharmacy checkout/payment is not enabled.


## Free test deployment notice

This package uses Render Free web service and Free PostgreSQL for initial testing. Render Free web services spin down after 15 minutes of inactivity and can take about a minute to wake. Free Render PostgreSQL is limited to 1 GB and expires 30 days after creation; export or migrate data before expiry. Free instances are for testing/hobby use, not production. Database migrations run in the build command because Render pre-deploy commands are only available on paid compute plans. Review current Render limits before deploying.
